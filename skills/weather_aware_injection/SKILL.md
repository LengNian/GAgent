# 天气感知流量注入建议

适用场景：
用户提供了设备所在城市（或可确定城市的设备 IP）和设备类型（有线/无线），希望根据当地实时天气生成流量注入参数建议。注入值为三项：平均时延、抖动、丢包率。当前注入 API 尚未接入，本 Skill 只输出建议值，不执行任何注入操作。

执行流程：
1. 确认城市与设备类型：
   - 城市：用户直接给出城市名则直接使用；只给出设备 IP 时，先调用 `query_device_by_ip` 从设备位置信息中确定城市。
   - 设备类型：用户已说明则直接使用；只给出 IP 时，取 `query_device_by_ip` 返回的有线/无线接入方式。
   - 城市和设备类型都缺少时先向用户询问，不得猜测。
2. 调用 `get_weather_now` 获取该城市的实时天气（温度、天气现象、风力、降水量、能见度等）。注意：天气数据只是中间结果，拿到后必须紧接着执行步骤 3-5 并在同一轮输出最终注入建议，不得把原始天气数据当作最终回复、不得等用户追问。
3. 根据天气现象确定注入参数范围，再根据实际数值（降水量、风速、能见度、温度）在范围内取值：

   | 天气现象 | 平均时延 | 抖动 | 丢包率 |
   |---------|---------|------|--------|
   | 晴/少云/阴 | 5–15ms | 1–3ms | 0.01–0.1% |
   | 小雨/毛毛雨 | 20–40ms | 5–12ms | 0.3–1% |
   | 中雨/大雨 | 40–80ms | 12–30ms | 1–3% |
   | 雷暴/强对流 | 80–200ms | 30–80ms | 3–8% |
   | 大雪/雾/霾（能见度低） | 50–120ms | 20–50ms | 2–5% |
   | 台风/龙卷风（极端） | 200–500ms | 80–150ms | 10–25% |

   取值规则：同等级内，降水量越大、风速越高、能见度越低、温度越极端，取值越靠近范围上限；反之靠近下限。

4. 根据设备类型调整：
   - 有线设备：直接使用上表值。
   - 无线设备：时延和丢包率各乘以 1.5（无线链路受天气影响更大）。
5. 输出结构化注入建议，包含：
   - 城市、当前天气现象、设备类型
   - 三项注入值（平均时延、抖动、丢包率）
   - 依据说明（为什么选这个等级、设备类型调整了什么）
   - 明确声明「当前仅为建议值，注入 API 未接入，不会执行实际操作」

约束：
- 只能调用当前 Agent 已授权的 MCP 工具。
- 天气数据必须来自 `get_weather_now` 工具返回，不得凭用户描述的日期或季节猜测天气。
- 获取天气后必须在同一轮完成步骤 3-5 并输出最终注入建议；不得仅返回天气数据就结束，不得要求用户再次询问才给建议。
- `get_weather_now` 失败或城市无法解析时，明确告知用户无法获取天气，回退为“晴/少云”等级的默认值并标注为回退。
- 当前不执行任何注入操作，只输出建议值。不得声称“已注入”或“注入成功”。
- 天气现象匹配上表中最接近的一行；同时出现多种恶劣现象（如雷暴+大雨）时取最严重的那一行。
- 输出结果必须包含明确的“仅为建议、未执行注入”声明。
