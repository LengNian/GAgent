# 设备健康巡检

适用场景：
用户想了解某台设备的整体健康状况（如“这台设备现在怎么样”“帮我给它做个体检”），但没有指定具体指标或告警维度。

执行流程：
1. 确认用户提供了设备 IP；缺少 IP 时先向用户询问，不调用工具猜测设备。
2. 调用 `query_device_by_ip` 获取设备基础信息（名称、类型、型号、位置、有线或无线、端口数量与 up/down、邻居数量），作为「设备与端口」维度。
3. 调用 `list_alarm_events` 获取该设备近期告警，作为「告警」维度。
4. 选择关键指标作为「指标」维度：先调用 `list_metric_names` 取该设备的精确指标名称，再用 `get_realtime_metric` 取少量最相关指标的当前值；指标数值只能来自指标工具，不得从 `query_device_by_ip` 的返回中读取，也不得凭用户说的中文指标名猜测参数。
5. 分别给出三个维度的结论，不做加权总分；某一维度缺少数据时，明确标注为“未知”。

约束：
- 只能调用当前 Agent 已授权的 MCP 工具。
- 三个维度各自标注正常/异常/未知，任一维度缺数据时不得用其他维度推断补齐。
- 不得把三个维度拼成“综合健康评分”或单一结论，须分维度呈现。
- 端口 up/down 只是计数，不等于设备在线或离线；本工具集不提供上下线判定，需要时必须明确说明无法确认。
- 本 Skill 只覆盖当前状态巡检；用户若要一段时间的指标趋势，应改用指标趋势分析流程。
- 指标维度默认只取少量（不超过 3 个）最相关指标的当前值，不逐个拉取全部指标。
