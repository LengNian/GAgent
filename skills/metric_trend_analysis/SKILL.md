# 指标趋势分析

适用场景：
用户询问设备某个监控指标在一段时间内的变化趋势、峰值、异常波动或是否持续升高/降低。

执行流程：
1. 确认用户提供了设备 IP；缺少 IP 时先向用户询问，不调用工具猜测设备。
2. 调用 `list_metric_names` 获取该设备的可用指标名称；用户说的中文指标（如“CPU 占用量”）必须在这份列表里找到逐字相同的精确名称。列表中没有对应指标时，不得调用 `get_metric_range` 试探，直接告知用户该设备未采集此指标。
3. 如果待查询指标不超过 5 个，对每个指标分别调用 `get_metric_range` 获取时间序列。用户没有指定时间范围时使用默认最近 1 小时；用户指定了范围时按用户范围传入，`start` 只写时长本身：过去 12 小时写 `12h`、30 分钟写 `30m`、7 天写 `7d`，不得加负号或其他前缀（`-12h` 会被解析成未来时间，窗口倒挂、查不到数据）。
4. 如果待查询指标超过 5 个，不逐个调用 `get_metric_range`；只对其中最相关的 5 个下钻，其余指标在报告中明确说明未查询，不得用 `query_device_by_ip` 的结果替代指标趋势。
5. 只有在历史数据不足以回答“当前值”时，才补充调用 `get_realtime_metric`。
6. 依据工具返回的数据说明趋势、峰值、低谷和明显异常；没有数据或数据不足时明确说明，不能自行推断。

约束：
- 只能调用当前 Agent 已授权的 MCP 工具。
- 工具调用可以分多轮进行，但每一步必须依据前一步工具结果。
- 不要把指标名称列表本身当作趋势结论。
- 单轮最多调用 5 次 `get_metric_range`。
- `query_device_by_ip` 只提供设备基础信息（名称、类型、型号、位置、有线/无线、端口计数、邻居数量），已不含指标数值；不得从中引用或推断任何指标的当前值与趋势。
- 超过 5 个指标时，应告知用户本次仅下钻了最相关的 5 个，并建议用户指定不超过 5 个指标后分批查询。
