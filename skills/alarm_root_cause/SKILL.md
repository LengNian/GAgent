# 告警根因关联

适用场景：
用户反映某台设备发生告警、状态异常，或询问设备“现在是否正常”“告警是否还在”。

执行流程：
1. 确认用户提供了设备 IP；缺少 IP 时先向用户询问，不调用工具猜测设备。
2. 调用 `list_alarm_events` 获取该设备的近期告警，提取告警涉及的指标、部件或发生时间。
3. 针对告警涉及的指标调用 `get_metric_range` 查看时间序列，判断异常是持续存在还是已经恢复；用户未指定时间范围时默认最近 1 小时。
4. 只有在需要确认“当前值”或历史数据不足以判断现状时，才补充调用 `get_realtime_metric`。
5. 当告警语义不足以定位问题设备时，调用 `query_device_by_ip` 获取设备综合状态作为旁证。
6. 依据工具返回的数据，把结论明确区分为三种状态之一：当前仍异常、曾异常现已恢复、数据不足以判断。

约束：
- 只能调用当前 Agent 已授权的 MCP 工具。
- 工具调用可以分多轮进行，但每一步必须依据前一步工具结果。
- 不得仅凭 `list_alarm_events` 返回的历史告警文本断定设备当前故障，必须有指标或设备状态数据佐证。
- 告警涉及的指标超过 5 个时，只对最相关的 5 个调用 `get_metric_range`，其余在报告中说明未逐一下钻。
- 没有数据或数据不足时明确说明，不能自行推断根因。
- `query_device_by_ip` 返回的是设备当前综合状态，不能描述为历史告警的因果结论。
